## 1. Что это за продукт

Учёт личных и семейных финансов: операции, категории, лимиты, цели, правила счетов,
доходность вкладов, инвестиции, переводы между счетами, импорт чеков (OCR),
экспорт профиля в JSON, автообновление по кнопке. Разворачивается в Docker на Synology / Xpenology.

Технически: ASP.NET Core 8 + EF Core + SQLite + JWT, SPA на React 18 / TypeScript / Vite.
Один процесс отдаёт и API, и статику. База — один файл SQLite (`data/app.db` в dev,
том `schitayka-data` в Docker).

## 4. Аудит 16.11.2026: что было не так и что сделано

Аудит сверял `PLAN.md` с фактическим кодом. Найдено 3 дефекта уровня P0 и 8 — P1.

### P0 — исправлено

| Дефект | Что сделано |
|---|---|
| `POST /api/budget/tx-for` падал с 500: внутри создавался контроллер, не зарегистрированный в DI; операция при этом уже сохранялась | Пересчёт через `AccountsController.RecalcAccountsOf` + `EvaluateAllAsync`, операция и пересчёт в одной транзакции. Тест в `EndpointFixesTests` |
| `POST /api/interest/payout` закрывал все начисления произвольной суммой из запроса | `PayoutDto.Amount` стал `decimal?`; сумма = сумма `Net` неоплаченных (или строгая сверка ±0,01), всё в транзакции, повторная выплата → 400. Тест добавлен |
| `IsTransfer` принимался из тела запроса — можно было вручную пометить операцию переводом и исказить сводку | Признак выставляет только сервер (`TransferService`), клиентское значение игнорируется в Create/Update. Тесты переписаны |

### P1 — исправлено

- Формула остатка была скопирована в четырёх местах → `backend/Services/AccountBalanceService.cs`
  (попутно убран N+1: один запрос по операциям вместо запроса на каждый счёт).
- `BankId` не проверялся → только системный банк или банк своей семьи (Create/Update).
- `AuthController`: NRE на пустых `email`/`password`; в JWT не было claim `email`,
  из-за чего не работал `SelfUpdate:AdminEmails`.
- Импорт чека проверял только Content-Type → теперь Content-Type **и** расширение
  плюс rate limit `import` (20/мин на IP).
- `SelfUpdateService`: `_gate` не использовался, версия не валидировалась, SHA256 был fail-open
  (при 404/сетевой ошибке обновление применялось) → семафор, строгий формат версии,
  fail-closed при отсутствии контрольной суммы.
- Демо-сид создавался при любом старте → только Development или `SCHITAYKA_SEED_DEMO=true`;
  супруге сеются стартовые категории.
- `GET /api/transfers/{id}` грузил все переводы пользователя → `TransferService.GetAsync`.

### Документация и конфигурация

## 5. Известные дефекты и ограничения (не исправлены)

### 5.1 Прогресс автообновления показывает «4325%» — B21

- **Симптом:** в настройках при обновлении видно «Скачиваем обновление… · 4325%»,
  хотя обновление проходит успешно.
- **Причина:** `backend/Services/SelfUpdateService.cs:217` — `Step(Downloading, 5 + p * 45, …)`,
  где `p` — процент скачивания (0…100). Получается шкала 5…4505 вместо 5…50.
  Фронтенд (`frontend/src/App.tsx:667`) печатает число как процент, а ширина полосы
  ограничена только снизу (`Math.max(3, apply.progress)`, строка 657).
- **Как исправить:** `5 + (int)Math.Round(p * 0.45)` в сервисе и
  `Math.min(100, Math.max(3, progress))` в UI. Записано в `PLAN.md` как B21.

### 5.2 Прочие ограничения

| Ограничение | Где зафиксировано |
|---|---|
| Отрицательный остаток маскируется (`Math.Max(0, …)`) — перерасход не виден | PLAN.md B19 |
| Legacy-«гармонизация» схемы в `Program.cs` (300–409) удаляет копии БД без пользователей и отстаёт от модели | PLAN.md B14 |
| Автосборка фронтенда в рантайме и в `dotnet build`; ошибки MSBuild-таргета глотаются | PLAN.md B16 |
| N+1 и полные выборки на чтении (`GET /api/accounts`, `budget/summary`) | PLAN.md B15 |
| Нет интеграционных тестов HTTP (`WebApplicationFactory`) — именно из-за этого P0-дефекты жили долго | PLAN.md B18 |
| QR-путь импорта (ФНС) и облачные OCR не реализованы — только локальный `tesseract` | PLAN.md B1, B2 |
| Экспорт профиля целиком, без `from/to` и `anonymize` | PLAN.md B4 |

## 7. Договорённости и решения (чтобы не пересматривать заново)

- **Баланс** считается только в `AccountBalanceService`; контроллеры и `TransferService` делегируют туда.
- **Перевод** — это запись `Transfer` + две операции с `IsTransfer=true`; флаг ставит сервер.
- **Проценты**: начисление отдельными записями `InterestAccrual`; выплата одной операцией
  на сумму `Net` неоплаченных начислений.
- **Миграции**: только EF Core; baseline для старых баз без `__EFMigrationsHistory`.
- **Релиз**: сначала коммит с изменениями, затем отдельный `chore(release): version x.y.z`;
  тег `vX.Y.Z`, релиз с тремя ассетами (docker.zip, app.zip, sha256), архив — с `-NoEnv`.
- **Секреты**: в репозитории и архивах нет ключей; `JWT_KEY` генерируется на NAS.
- Сознательно **не** менялись: `Math.Max(0, …)`, legacy-гармонизация, автосборка фронтенда,
  N+1 в проекции счетов — это отдельные задачи бэклога (B19, B14, B16, B15).
