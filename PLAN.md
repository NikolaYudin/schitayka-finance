## Принципы

1. **Данные пользователя неприкосновенны**: не использовать `EnsureDeleted()` в рабочем режиме, не трогать рабочие базы без явного запроса.
2. **Схема БД — через EF Core Migrations**; обратная совместимость со старыми базами.
3. **Приватность по умолчанию**: чувствительные данные не логируются и не отправляются наружу без необходимости.
4. **Каждая фича — API + UI + тесты + документация** (по возможности в рамках задачи).
5. **Секреты не хранятся в репозитории и релизных архивах**.

### 2. Вкладка «Долги»

**Цель:** учитывать денежные обязательства пользователя (кому должен / кто должен пользователю) отдельно от регулярных платежей.

**Предлагаемая структура (черновик):**
- Сущность `Debt`: направление (`я должен` / `мне должны`), контрагент (человек/организация), название, основная сумма, остаток, валюта, дата возникновения, срок/дата возврата (опц.), процент/условия (опц.), связанный счёт (опц.), заметка, статус (`активен`, `закрыт`, `просрочен`).
- История событий/операций по долгу: выдача, частичный возврат, начисление/оплата процентов, списание/корректировка (с привязкой к транзакции при необходимости).
- **Отображение на дашборде:** отдельный виджет «Долги» с переключателем видимости (показывать/скрывать) и краткой сводкой (сумма «я должен», «мне должны», ближайшие сроки).

### 3. Вкладка «Обязательные платежи»

**Цель:** планировать и контролировать регулярные/обязательные платежи (не обязательно являющиеся долгом).

**Предлагаемая структура (черновик):**
- Сущность `Obligation` (обязательный платёж): название, получатель, категория, сумма (фикс/ожидаемая), периодичность (`разово`, `ежемесячно`, `ежеквартально`, `ежегодно`, произвольно), дата следующего платежа, день платежа, счёт списания (опц.), напоминание (опц.), статус (`активен`, `пауза`, `завершён`), привязка к долгу (опц.).
- Факт оплаты: отметка выполнения/создание операции, перенос даты следующего платежа, просрочка.
- **Отображение на дашборде:** виджет «Обязательные платежи» с переключателем видимости (ближайшие платежи, сумма за период, просроченные).

### 4. Пересечение «Долги» и «Обязательные платежи»

**Принцип:** это разные сущности, которые могут быть связаны.

- **Долг без обязательного платежа:** например, займ у коллеги без графика — создаётся только `Debt`, платежи фиксируются как события возврата.
- **Долг с обязательными платежами:** например, ипотека/кредит — `Debt` (остаток, условия) + связанный `Obligation`/график платежей (дата, сумма, напоминания). Оплата платежа может уменьшать остаток долга.
- **Обязательный платёж без долга:** коммунальные услуги, подписки, налоги — только `Obligation`.
- В UI/модели предусмотреть связь `Obligation.debtId` (nullable), отображение связанного долга в карточке платежа и предстоящих платежей в карточке долга.
- Дашборд-переключатели видимости настраиваются независимо для виджетов «Долги», «Обязательные платежи» (и календаря), но связанные элементы должны быть согласованы (без дублирования сумм в общей аналитике).

### 5. Вкладка «Календарь событий»

**Цель:** единое представление дат и событий по финансам.

**Предлагаемая структура (черновик):**
- Источники событий: обязательные платежи, даты возврата/платежей по долгам, даты окончания вкладов, начисления/выплаты, пользовательские события/напоминания.
- Представления: месяц/неделя/список «ближайшие»; фильтры по типу события.
- Сущность пользовательского события (опц.): название, дата/время, тип, сумма (опц.), связь с долгом/платежом/счётом (опц.), напоминание.
- **Отображение на дашборде:** виджет «Ближайшие события» с переключателем видимости (N ближайших событий/платежей).

## Процесс релиза (кратко)

1. Подготовить изменения, обновить документацию (`STATUS`, `CHECKLIST`, `PLAN`, `README` при необходимости).
2. Проверить: `dotnet build SchitayKa.sln -c Release`, `dotnet test`.
3. Обновить `VERSION`, подготовить заметки релиза.
4. Коммит `chore(release): version X.Y.Z`, тег `vX.Y.Z`, push ветки и тега.
5. Собрать артефакты: `pwsh -NoProfile -File deploy/xpenology/release/build-release.ps1`.
6. Опубликовать GitHub Release с `schitayka-X.Y.Z-docker.zip`, `schitayka-X.Y.Z-app.zip`, `schitayka-X.Y.Z-app.zip.sha256`.
