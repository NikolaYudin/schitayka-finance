# СчитайКа (SchitayKa) 🧮

Веб-приложение для учёта личных финансов: доходы и расходы, лимиты по категориям,
анализ бюджета, финансовые цели и персонализированные рекомендации.

## Возможности
- **Переводы между своими счетами** — в окне новой операции выберите «Перевод», счета «Откуда/Куда» и сумму. В журнале переводы показаны отдельно; отмена удаляет обе стороны и пересчитывает остатки. Переводы не дают кэшбэк и не увеличивают доходы/расходы.
- **Учёт операций** — быстрый ввод дохода/расхода (FAB ＋), журнал по месяцам с итогами.
- **Категории** — справочник категорий доходов/расходов (стартовый набор создаётся при первичном создании учётной записи, например в демо-режиме); можно добавлять свои.
- **Лимиты бюджета** — месячные лимиты расходов по категориям с прогресс-барами и контролем перерасхода.
- **Финансовые цели** — копилки с целевой суммой и сроком; приложение считает, сколько нужно откладывать в месяц.
- **Анализ** — динамика доходов/расходов за 6 месяцев, структура расходов по категориям, норма сбережений.
- **Персональные рекомендации** — советы по данным пользователя: превышение лимитов, низкая норма сбережений,
  отсутствие подушки безопасности, крупные траты без лимита, нерегулярный учёт и др.
- **Версия и обновления** — приложение показывает текущую версию/коммит, проверяет последний коммит
  в GitHub и предлагает обновиться; на NAS есть скрипт замены кода без пересоздания контейнера.
  Есть кнопка **«Обновить сейчас»**: приложение само скачивает сборку из GitHub Releases,
  проверяет контрольную сумму, делает резервную копию файлов и перезапускается — база не страдает.
- **Импорт из чека или скриншота** — в окне новой операции: локальный OCR (tesseract) распознаёт
  фото чека/скриншот банка, QR чека ФНС разбирается локально (вставка строки, файл или камера),
  распознаются позиции — выбранные можно сохранить отдельными операциями. Удалённый vision-OCR
  подключается только явной настройкой с ключом; по умолчанию изображения никуда не отправляются.
- **Экспорт JSON для ИИ** — в настройках одна кнопка: полный профиль (счета, операции, категории,
  лимиты, цели, правила, резервы, месячные агрегаты) одним файлом для анализа ИИ-агентом.
  Можно задать диапазон дат, лимит операций и обезличить персональные данные.
- **Оформление** — премиальный macOS-стиль: стекломорфизм, мягкие тени, крупные радиусы и системные цвета Apple
  (синий `#007AFF`, зелёный `#34C759`, красный `#FF3B30`, фиолетовый `#AF52DE`). Светлая, тёмная и системная тема;
  переключатель в шапке и в настройках, выбор запоминается.
- **Счета** — дебетовые/кредитные карты, наличные и вклады; карточки в сетке, архивные счета скрываются из итогов. Переводы между счетами не искажают доходы и расходы.
- **Доходность вкладов и накопительных счетов** — для счёта типа «Вклад / копилка» задаётся **ставка % годовых**
  вместо кэшбэка и режим начисления (ежедневно на остаток с капитализацией / с выплатой раз в месяц / в конце срока).
  Приложение считает доход по формуле Act/365, показывает прогноз за месяц и год до и после НДФЛ,
  ведёт журнал начислений и позволяет зафиксировать выплату одной операцией.
- **Мониторинг инвестиций** — портфели с привязкой к банку (Т‑Банк, Сбер, ВТБ и др. + свои банки),
  продукт (накопительный счёт / вклад / брокерский / ИИС / **Инвесткопилка**) и стратегия Инвесткопилки
  («Всегда в плюсе», «Сбалансированная», «Стабильные компании»). Считаются стоимость активов, доходность,
  налоговый ориентир и **сравнение с накопительным счётом Т‑Банка (6 % / 8 % с подпиской Pro)** — видно,
  во сколько обходится риск. Деньги в инвестициях не застрахованы по АСВ.
- **Банки** — справочник системных и своих банков с привязкой к счетам; в настройках можно видеть, используется ли банк, скрывать неиспользуемые из списка и удалять неиспользуемые свои банки.
- **Долги** — отдельная вкладка «Долги»: кому должны вы и кто должен вам, суммы и остатки, сроки, ставка и условия,
  история событий (возврат, проценты, корректировка, списание) и необязательная операция по счёту при возврате.
  Долги не входят в доходы/расходы бюджета; на дашборде — отдельный виджет с переключателем видимости.
- **Обязательные платежи** — вкладка «Платежи»: регулярные траты (коммуналка, подписки, налоги, кредит) с получателем,
  категорией, суммой и периодичностью; дата следующего платежа, день платежа, просрочки, история оплат и связь с долгом.
  Сам платёж — план и в бюджет не входит; операция по счёту создаётся по галочке при оплате. Виджет на дашборде включается в настройках.
  Для платежа, связанного с долгом «я должен», можно дополнительно уменьшить остаток долга — без второго движения денег:
  операция остаётся только у факта оплаты, а история долга получает событие возврата. Связанные платежи видны в карточке долга.
- **Календарь событий** — вкладка «Календарь» с видами «месяц / неделя / ближайшие» и фильтрами по источникам:
  обязательные платежи, сроки долгов, окончание вкладов, начисления процентов и свои события/напоминания.
  Свои события можно привязать к долгу, платежу или счёту; на дашборде — виджет «Ближайшие события» со своим переключателем. Календарь не влияет на бюджет.
- **Вход** — email + пароль (PBKDF2, JWT). При первом запуске мастер-профиль в БД создаёт администратора, который затем создаёт пользователей семьи. Публичная регистрация отключена. Вход через Яндекс не используется. Тема интерфейса синхронизируется между устройствами.
- **Семейные счета** — члены семьи видят счета друг друга **на дашборде** (блок «Счета семьи») и во вкладке «Счета».
  По счёту семьи можно сразу создать операцию — она записывается владельцу счёта, а личный бюджет
  при этом не искажается. Полное управление (архив, переименование, лимиты) остаётся во вкладке «Счета».
  **Категории доходов и расходов общие для семьи**: все члены видят и редактируют один список (помечен 🏠),
  одноимённые категории при объединении семей сливаются. Бюджетные лимиты остаются личными.
  В разделах «Долги», «Платежи» и «Календарь» есть общий переключатель «Я / Вся семья» (как на дашборде):
  в семейном режиме видны и редактируются записи всех членов семьи, а владелец записи подписан в карточке.
- **Профиль** — клик по аватару в правом верхнем углу открывает меню: «Профиль и настройки» и «Выйти из профиля».
- **Демо-данные** — в Development создаётся аккаунт `demo@schitayka.ru / demo123` с операциями, лимитами и целями. В production демо по умолчанию **не создаётся**; включить можно явно — `SCHITAYKA_SEED_DEMO=true` (в Docker: `SEED_DEMO=true` в `.env`).
- **NAS** — развёртывание из zip-дистрибутива (Container Manager) подтверждено пользователем как работающее на реальном NAS (17.11.2026).

## Архитектура
- `backend/` — ASP.NET Core 8 (Minimal hosting + контроллеры), SQLite через EF Core, JWT-автентификация, Swagger (`/swagger`).
- `frontend/` — React 18 + TypeScript + Vite (SPA с hash-роутингом), собирается в `backend/wwwroot`.
- Схема БД обновляется **EF Core Migrations** (`backend/Migrations`); старые базы без истории миграций автоматически помечаются baseline-миграцией без потери данных.
- `backend.Tests/` — xUnit-тесты, `.github/workflows/ci.yml` — сборка, тесты и проверка типов фронтенда.

### Структура проекта

```
schitayka-finance/
├── backend/           # ASP.NET Core 8: Program.cs, Controllers/, Services/, Data/, Migrations/
├── backend.Tests/     # xUnit-тесты (сервисы, калькуляторы, регрессии)
├── frontend/          # React 18 + TypeScript + Vite, собирается в backend/wwwroot
├── deploy/xpenology/  # Dockerfile, docker-compose, INSTALL.md, упаковщик релиза
├── docs/              # README (точка входа), STATUS (история и дефекты), PROJECT-MAP (карта файлов)
├── PLAN.md            # план работ, бэклог B1–B21, журнал исправлений
├── VERSION            # версия приложения
└── SchitayKa.sln      # backend + backend.Tests
```

Подробная карта — за что отвечает каждый файл, все маршруты API, сущности БД, потоки данных
и «где искать функционал»: [`docs/PROJECT-MAP.md`](docs/PROJECT-MAP.md).

Ключевые места: конфигурация и старт — `backend/Program.cs`; расчёт остатков — один файл
`backend/Services/AccountBalanceService.cs`; контроллеры — `backend/Controllers/`;
экраны — `frontend/src/App.tsx` (каркас) и `frontend/src/components.tsx` (дашборд).

### Дизайн
Интерфейс построен по брифу `schitayka-design-prompt.md`:
- стеклянные поверхности (`backdrop-filter: blur(...) saturate(...)`), тонкие полупрозрачные границы и мягкие тени;
- крупные радиусы (до 32px), воздушные отступы и чёткая типографическая иерархия;
- дашборд: hero-блок общего баланса, кольцо нормы сбережений, KPI, карточки счетов в духе Apple Wallet,
  столбчатая динамика за 6 месяцев, кольцевая структура расходов, лимиты и рекомендации;
- плавные «яблочные» анимации появления, hover и раскрытия FAB; поддержка `prefers-reduced-motion`;
- адаптив: мобильное выдвижное меню, одноколоночные карточки и компактная шапка.

## Запуск (Windows, как в оригинальной наработке)
1. Установите [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) и [Node.js LTS](https://nodejs.org).
2. Один раз запустите `setup.cmd` (проверит окружение, `npm install`, `npm run build`).
3. Откройте `SchitayKa.sln` в Visual Studio и нажмите **F5** — фронтенд будет собираться автоматически,
   браузер откроется на <http://localhost:5023>.

## Запуск (кроссплатформенно)
```bash
cd frontend && npm install && npm run build   # сборка SPA в backend/wwwroot
cd ../backend && dotnet run                    # http://localhost:5023
```
Режим разработки без сборки SPA: `cd frontend && npm run dev` (Vite проксирует `/api` на :5023,
а бэкенд в Development сам проксирует страницы на Vite, если wwwroot отсутствует).

## Запуск в Docker / Synology (Container Manager)

### Вариант 1. Zip-дистрибутив (рекомендуется)

```powershell
pwsh -File deploy/xpenology/release/build-release.ps1
# → dist/schitayka-1.1.0-docker.zip
```

Архив распаковывается в `/volume1/docker` (получится `/volume1/docker/schitayka`),
и проект создаётся прямо в Container Manager — без git, SSH и правки путей.
Внутри уже есть `.env` с ключом, `scripts/` для бэкапа/обновления и подробный `README.md`.
Архитектура и инструкция: [`deploy/xpenology/release/PACKAGING.md`](deploy/xpenology/release/PACKAGING.md),
инструкция внутри архива — [`deploy/xpenology/release/README.md`](deploy/xpenology/release/README.md),
план — `PLAN.md`, Задача 4.

### Вариант 2. Из git-клона

Готовая папка для сборки: [`deploy/xpenology`](deploy/xpenology/README.md) — multi-stage `Dockerfile`,
`docker-compose.yml`, `.env.example` и пошаговая инструкция для DSM 7.2 / Xpenology.
**Полная инструкция с нуля:** [`deploy/xpenology/INSTALL.md`](deploy/xpenology/INSTALL.md).

```bash
cd deploy/xpenology
cp .env.example .env        # обязательно задать JWT_KEY (>= 32 символов)
docker compose up -d --build
```

Приложение: `http://<IP-НАС>:5023`. SQLite хранится в именованном томе `schitayka-data`,
демо-аккаунт в production отключён (`SEED_DEMO=false`), healthcheck — `/api/health`.

Обновление на NAS: `sh deploy/xpenology/update-inplace.sh` — заменяет код внутри
существующего контейнера и перезапускает его, не пересоздавая контейнер и не трогая
том с базой. Если менялись compose/env — `sh deploy/xpenology/update.sh`.
Подробнее: [`deploy/xpenology/README.md`](deploy/xpenology/README.md#7-версия-и-обновление).

> В Production ключ JWT обязателен: задайте `Jwt__Key` (не короче 32 байт) через переменную окружения,
> user-secrets или `appsettings.Production.json`. Без него приложение осознанно не стартует.

## Запуск в VS Code
1. Установите расширение **C#** (`ms-dotnettools.csharp`).
2. Откройте папку репозитория целиком (**File → Open Folder**), а не только `frontend`.
3. Нажмите **F5** → конфигурация «SchitayKa: backend (5023)»: VS Code выполнит `dotnet restore`,
   сборку и запустит сервер; браузер откроется на <http://localhost:5023>.
   Порт 5023 зафиксирован в `Program.cs`, поэтому он одинаков при любом способе запуска
   (VS, VS Code, `dotnet run`) и совпадает с прокси Vite.
4. Быстрый путь без отладчика: терминал → `cd backend && dotnet run`.
   Команду `dotnet run` внутри `frontend` выполнять не нужно — там нет .NET-проекта.
   Для фронтенда в dev-режиме используйте задачу **Tasks → Run Task → frontend-dev (vite :5173)**.

## API (кратко)
| Метод | Путь | Описание |
|---|---|---|
| POST | /api/auth/login | получение JWT |
| GET | /api/auth/me | текущий пользователь |
| GET/POST/PUT/DELETE | /api/categories | справочник категорий |
| GET/POST/PUT/DELETE | /api/transactions?month=&year= | операции |
| GET/POST/PUT/DELETE | /api/goals, /api/goals/{id}/deposit | финансовые цели |
| GET/POST/DELETE | /api/limits?year=&month= | месячные лимиты (upsert) |
| GET | /api/budget/summary | сводка + рекомендации + familyAccounts (счета семьи) |
| POST | /api/budget/start-balance | стартовый баланс «на счетах» |
| GET | /api/interest/forecast/{accountId} | прогноз доходности вклада/копилки (ставка % годовых) |
| GET | /api/interest/accruals | журнал начислений процентов |
| POST | /api/interest/accrue/{accountId} · /payout/{accountId} | начислить проценты · зафиксировать выплату |
| GET | /api/banks | справочник банков (для мониторинга инвестиций) |
| GET/POST/PUT/DELETE | /api/investments, /api/investments/{id}/holdings | портфели и позиции по банкам |
| GET | /api/investments/summary | сводка по инвестициям и сравнение с накопительным счётом |
| GET/POST/PUT/DELETE | /api/debts, /api/debts/{id} | долги (фильтр `?filter=active\|closed\|all`) и история событий `{id}/events`; `{id}/close\|reopen` |
| GET | /api/debts/summary | сводка по долгам для дашборда (я должен / мне должны / просрочка) |
| GET | /api/debts/{id} | карточка долга с историей и связанными платежами (`linkedObligations`) |
| GET/POST/PUT/DELETE | /api/obligations, /api/obligations/{id} | обязательные платежи (фильтр `?filter=active\|paused\|completed\|all`) |
| POST/DELETE | /api/obligations/{id}/pay, /api/obligations/{id}/payments/{paymentId} | факт оплаты (`createTransaction` — операция, `reduceDebt` — уменьшить остаток связанного долга) и его удаление |
| POST | /api/obligations/{id}/pause · /resume · /complete | смена состояния платежа |
| GET | /api/obligations/summary | сводка по обязательным платежам для дашборда (ближайшие, сумма за месяц, просрочка) |
| GET | /api/calendar · /api/calendar/upcoming | события календаря в диапазоне (`from`, `to`, `types`) и ближайшие (`take`, `days`) |
| POST/PUT/DELETE | /api/calendar/events, /api/calendar/events/{id} | пользовательские события и напоминания |
| GET | /api/version · /api/version/check | текущая версия и проверка обновлений по GitHub |
| GET/POST | /api/version/apply · /apply/status | автообновление по кнопке: запуск и статус с прогрессом (включается `SELFUPDATE_ENABLED=true`, см. `deploy/xpenology/INSTALL.md` п. 7.5) |
| POST | /api/import/receipt · /receipt/text · /receipt/qr | распознавание чека/скриншота, разбор текста и QR ФНС |
| POST | /api/setup/admin · /api/admin/users | первичный администратор и управление пользователями семьи |
| GET/PUT | /api/settings/appearance | синхронизация темы интерфейса |
| GET | /api/export/profile | полный JSON-профиль для ИИ-анализа |
| GET | /api/health | проверка работоспособности |

Все данные изолированы по пользователю (фильтрация по UserId из JWT).
